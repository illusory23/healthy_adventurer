# 《健康的冒险者的一天》工作流程

> 本文件整理自项目根《工作前置.txt》（原意不变，仅结构化重排，便于逐条执行）。

## 一、开工前置（动手前必做）

1. **读取文档**：读 `D:\游戏\健康的冒险者的一天` 路径下的全部 `.md` 文件（01~10 模块文档 + README）。
2. **读取数据表**：读 `D:\游戏\健康的冒险者的一天\数据表` 路径下的全部 `.csv` 文件。

## 二、改动后的固定动作

3. **更新文档**：更新代码后，记得更新对应文档的相关部分。
4. **备份**：每次修改完代码后，自动备份到 `D:\游戏\健康的冒险者的一天\代码备份`；**体验版不需要备份**。
5. **同步范围**：未特殊说明的更新 = **全部同步更新**；说"创造相关"时指的是**原型版本**（创造模式测试原型\健康的冒险者的一天.html）。
6. **更新顺序（v1.51 起）**：
   1. **先更新 Flask 版**（`Flask版\static\game.html` + `Flask版\data\static_data.json` 等）；
   2. 再同步**创造模式原型**（数据段 + 跑 `创造模式测试原型\_sync_proto.py --apply`）；
   3. 最后同步**体验版**（cp）。
   - **数据表改动必须通过三方对拍**（`Flask版\_parity_check.py`，对拍 = 原型 ↔ 前端 ↔ 服务端）。

## 三、会话维护

7. **token 接近 1M 上限时**：自动压缩摘要、总结对话记录，保存在 `D:\游戏\健康的冒险者的一天\ai修改对话记录`。

## 四、实操要点（执行经验，供理解上文的"怎么做"）

- **体验版同步明细**：体验版目录（`健康冒险者的一天体验版V1.1\`）需同步 4 个文件——`game.html`（根目录 + `static\` 两份内容相同）、`game.py`（Flask 版为 LF，写入体验版时转 CRLF）、`app.py`（直接复制）。
- **换行约定**：`game.html` **LF**（Flask 版与体验版均为 LF，v1.60 实核）；`game.py` LF（写入体验版时转 CRLF）；`test_game.py` CRLF；`.bat` 纯 ASCII + CRLF。
- **一键推送 GitHub**：根目录 `一键推送.bat`——`git add -A` → 提交（可带参数或交互输入说明）→ `pull --rebase` → `git push`。远端走 **SSH-over-443**（`ssh://git@ssh.github.com:443/...`，`core.sshCommand` 已配绝对路径），**勿改回 HTTPS**（本机 HTTPS 通道不通）。
- **cp 方向限制**：`cp` 只允许 `game.html → 体验版` 方向；原型 → game.html 的同步必须走 `_sync_proto.py`（或逐段 Edit），禁止直接用 cp 覆盖，防止桥接层丢失。
- **改完必跑全套测试**：`python run_all_tests.py`（根目录，6 套：smoke / 创造模式 / 核心逻辑 / API / 桥接复验 / 公式对拍）。
- **改了 game.py / app.py / game.html 后提醒用户重启服务器**。
- **数据表更新**：数据来源改动后跑 `数据表\_生成数据表.js` 重新生成全部 CSV。
