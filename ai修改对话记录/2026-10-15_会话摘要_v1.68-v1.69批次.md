### B. v1.69 · 大成功 = 全部奖励 ×2
口径：`ok && crit`（掷 1–5 且成功）时——

| 位置（game.py） | 原 | 现 |
|---|---|---|
| 报酬 | `gold = round(gold*1.2)` | **`gold *= 2`** |
| 经验 | 无 crit 项 | **`if crit: exp *= 2`** |
| 材料 | 无 crit 项 | **`if crit: n2 *= 2`**（掉率/数量加成之后、每项独立判定） |
| 声望 | `rep += 5` | **`rep *= 2`** |
| 贡献 | 无 crit 项 | **`if ok and crit: con *= 2`** |

- **连锁**：递交型委托的 `gold *= 2` 在其后 → **大成功 + 上交 = 报酬 ×4**（符合「全部双倍」字面，已写入 03 文档）。
- 大失败（96–100）与传奇事件分支不变；组队副本「掷 1~5 加 2 格」是另一套机制，未动。
- 文案：`game.html`「掷出 1–5 为大成功（**全部奖励 ×2**）」、「大成功：**声望 ×2**」；文档 03（大成功表）+ 04（声望来源表）。
- 三端（Flask 版 / 原型 / 体验版）+ `test_game.py` 新增 4b 节（锁 `game.rand` 的分支用例，验证五项各自 ×2）。

### D. 谈判卷轴定价审查 + 两个坑 + 馈赠补发
- **结论（1.2 金确实不合理）**：1.2 金 = 保本需基础报酬 ≥ **8 金** → **Lv1–Lv3 必亏**（Lv3 最高档也只值 0.72 金）、Lv4 平手、Lv5 才赚 4.3 倍；同店专注药剂 6 金、旅行干粮 3 金；健康完美档次日全委托 +15% 是**免费**的同类效果。→ **涨价到 6 金**（`SHOP` 三端 + `static_data.json` + 数据表 CSV + 06 文档）。
- **坑①（用了白烧）**：`use_item` 用 `max()` 写 `rare_next_pay` → 身上已有稀有事件 +25% 时，卷轴被吞、**白烧 1.2 金**。新增 `_use_next_buff(s, key, add, item)`：已有加成 ≥ 本次 → **不消耗道具**并提示（幸运币 / 专注药剂 / 谈判卷轴三处共用）。
- **坑②（失败照清）**：结算时**失败也清 buff** → 改为 **`if ok:` 才清零**（失败保留到下一次委托）；道具说明与结算文案补「失败不消耗」。
- **「意外的馈赠」补发**：`try_rare_event(..., res=...)` 委托触发时 `add = round(res["gold"]*0.5)` → 同步 `res.gold / s.money / s.daily.gold`，日志与卡片写「报酬 +50%」；探索侧仍是「下一次委托 +50%」（08 文档措辞已对齐代码）。

### E. 交互式改档工具（用户口中的「创造模式」，Flask 版专属）
三件套：**`Flask版/devops.py`（操作库） + `存档工具.py`（入口 A·离线/菜单） + `app.py::POST /admin/dev`（入口 B·在线）**

- **`devops.py`（新）**：**40 项纯函数**、分 9 组（1 数值 / 2 委托 / 3 健康 / 4 资产 / 5 养成 / 6 收集 / 7 探索与世界 / 8 复位 / 9 高级）；只依赖 `game.py`，**不做 I/O、不加锁**；失败一律 `raise OpError(文案)`。
  - **掷骰值可控**：`@contextlib.contextmanager fixed_roll(roll)` 临时替换 `game.rand`；`roll` 留空 = 真实随机，`1` = 大成功，`96` = 大失败，也可 1~100。
  - **踩坑记**：`run_op(s, op_name, **kw)` 的形参**不能叫 `name`**——材料/道具/装备/宠物等操作的参数就叫 `name`，会撞成 `got multiple values for argument 'name'`。
  - `op_raw_replace` 加防手滑：识别字段 <8 个就拒绝（`import_save_state` 对陌生字段是「全丢 + 补默认」，随手贴 `{"x":1}` 也能过 → 整档抹成新号）。
- **`存档工具.py`**：**无参数运行 = 交互菜单**（原 8 个命令行子命令全部保留、行为不变）。
  - 自动判模式：`_server_up()` 探测 5899 → 在跑 = **在线**（走 `/admin/dev`，改完即时生效、游戏里能看到掷骰动画）；没跑 = **离线**（直接读写库，改完启动游戏生效）；`[m]` 手动切（手动后不再自动跟随）。
  - 菜单：账号列表 → 9 类操作 → 逐参数提示；`[a]` 账号子菜单（摘要 / 全量 JSON / 导出 / 整档替换 / **回滚到某次自动备份**）。
  - 离线写档兜底：进菜单后又把服务开起来 → 检测到就**中止写入**并提示切在线模式。
- **`app.py::POST /admin/dev`**：**仅本机**（与 `/admin` 同门槛 `_is_local_host()`：回环地址 + 本机 Host + 无 XFF）；在 `_lock_for(uid)` 内 `_load → catch_up → deepcopy → run_op → flush_event_log + save_user_state`；操作跑在**副本**上（失败 = 原档分毫未动）；写库前 `_backup_state()` 备份整档到 `data/backups/manual-user<id>-*.json`（与离线工具同命名，可互相回滚）。
- 体例：`{"uid": 3, "op": "finish", "args": {"which": "all", "roll": "1", "silent": "0"}}` → `{"ok": true, "msg": "已按骰值 1 结算：…大成功！", "msgs": [...], "backup": "manual-user3-….json"}`。
