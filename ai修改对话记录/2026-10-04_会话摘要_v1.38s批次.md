### 1. 探索详情保密（`showRegionDetail` + `seenItems`）

- **未获得过的掉落显示「？？？」**（中性色徽章，不泄露品级），获得过一次后**永久**正常展示。
- 三套判定来源：
  - **材料** → `S.seenMats`（与图鉴共用；懒合并：当前持有自动计入）+ `S.mats[n]>0` 兜底；
  - **规则道具** → 新增 **`S.seenItems`**（新字段：`newState` 初始字段 + `migrate` 补齐 + **render 懒合并当前持有**；用掉后记录保留）；
  - **旧宝箱** → 在**探索结算开出那一刻**显式写入 `seenItems`（原型 `exploreFinishCheck` / 服务端 `explore_finish_check` 旧宝箱分支）。
- 展示：已知材料保留品质徽章（`t-品质`）；未知/道具/宝箱统一 中性 `？？？` chip（`_dropChip` 辅助函数）。
- Flask 三端链路：服务端 `new_state` 加 `"seen_items": []`、旧宝箱分支写入、`app.py _payload` 懒合并（与 `seen_mats` 同处）；前端 `adaptState` camelKey 自动映射（无需手改）；`import_save_state` 按 `new_state` 字段白名单自动保留。
- migrate_state（py）走 `base = new_state()` 补全，无需单独改。

### 2. 升级详情兜底弹窗（`checkFx` → `queueLevelUpDetail`）

- **根因**：v1.38r 的升级详情只挂在 `checkLevelUp()`（结算时经验达标）与 Flask 服务端 `levelups` 队列上；**创造模式直接改等级等"不经结算"的路径**只触发 `checkFx` 的 celebrateFx 小动画 → 无弹窗。
- **修复**：`checkFx` 检测到**等级上升**（`S.lvIdx > _lastLvFx`，原 `!==` 会在调低等级时误放"升级！"演出，顺带修正）时：
  - 从 `_lastLvFx+1` 到 `S.lvIdx` **逐级补入队**（跳级如 0→2 会补 Lv2、Lv3 两个详情）；
  - `setTimeout(flushResults, 500)` 驱动队列（弹结算结果之后依次弹出）；
- **去重/兼容**（新增 `queueLevelUpDetail(idx)` 统一入口）：
  - `checkLevelUp` 的 `levelupQueue.push` 改走该函数（同级 `indexOf` 去重——防 checkFx 与 checkLevelUp 双弹）；
  - **Flask 环境跳过**：`Array.isArray(S.levelups)` 时直接 return（服务端队列驱动，避免本地兜底双弹）；
  - 等级调低（创造模式减等级）不再触发演出/弹窗。
- `LEVEL_INFO` 无 idx 0（Lv1 无解锁内容）→ `showLevelUpDetail` 的 `if(!info)` 安全跳过。

### 3. 旧宝箱装备奖励恢复（与文档对齐）

- **背景**：`07_探索系统.md` 旧宝箱表写「随机普通~精良装备 ×1 | 10%」，三端代码实际为「旧宝箱（空的）」——某次改动删了装备奖励而文档未同步；用户确认按文档**加回去**。
- **实现**（原型 / game.html 镜像 / game.py 三端）：旧宝箱 `sub ≥ 0.9` 的 10% 档——
  - 从 **尚未拥有**（`S.gear` 背包与 `S.equipped` 四槽**均无**）的**普通~精良**装备（`GEAR` 品质列第 1 位）中随机 1 件 → `gear` 入包，gains 记「旧宝箱开出 装备「××」」；
  - 该类装备**全部拥有时空箱**（保留「旧宝箱（空的）」文案）；
  - 原型 `Math.random()` 抽取（消耗一个随机数）/ Python `random.choice(pool)`（getrandbits，不走 `random.random()`，mock 随机序列时无需留位）。

## 六、v1.38s3 补充（用户三次反馈：创造档池数量不跟随等级）

- **现象**："创造档 Lv5 但当前委托刷新只显示 3 个委托可选"。
- **根因（设计+工具缺环，非 bug）**：刷新池的抽取数量 `CFG.drawCount[S.lvIdx]`（1/3/5/6/8）由**抽池那一刻的等级**决定，池一旦抽出即固定（"刷新池必须落库、同批次内容不变"设计原则）；创造模式改等级不经过刷新点 → 池停留在旧等级数量（3 = lvIdx 1 的抽取数）。
- **修复（仅原型创造块）**：新增 `creRedrawPool()`——三个改等级入口（`creApplyBasic` 基础数值面板 / `creMaxLevel` 🏅满级 / `creMaxAll` 🧰全部拉满）在**等级实际变化时**调用之：按当前刷新点 `drawPool()` 重抽 `S.pool.list`（**刷新点 / 接取窗口 bornTs / taken 状态均不变**；无池或旧刷新点时跳过交给 tick）。
- **用户当前批次的直接解法**：既有的「🔄 立即刷新委托」按钮 = 无视时间段重抽 + 窗口自此刻重计（已存在于创造面板）。
- 测试：creator 58→**60**（满级重抽为 8 个 / 等级未变不重抽）；smoke 200 不变全过。**仅原型改动**——Flask 前端（无创造块）、服务端、体验版均不涉及，服务器无需重启。
- 备份重新生成；README 加 v1.38s3 行。
