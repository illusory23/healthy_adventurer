## 一、项目结构与铁律

| 文件 | 角色 |
|---|---|
| `原型\健康的冒险者的一天.html` | 单机原型：**数据源头**（C/M/GEAR/CFG/REGIONS/recipes/ITEM_DESC…）+ smoke 测试载体 + **🛠 创造模式（v1.38d，独立 `<script id="creator-mode">` 块）** |
| `Flask版\static\game.html` | 原型镜像 + 桥接层（同文件两套同名函数，**后定义覆盖前者**；含 localStorage 兼容层） |
| `Flask版\game.py` + `app.py` | 服务端权威逻辑 + 路由与动作分发（存档服务端化） |

- **三处同步**：改任何内容都要过 原型 → front → game.py；纯 UI 至少原型 + front 两处
- **数据导出**：原型数据变更后必须 `cd Flask版 && node tools_export_data.js`（生成 data/static_data.json）再重启
- front 桥接动作（被覆盖的那批：toggleTask/toggleMeal/addMulti/feedPet/evolvePet/cook/craft/useItem/equip…）→ `apiCall`
- 服务端 state 为 snake_case（`seen_mats` / `pet_data`…），front 经 `adaptState` 自动 camelKey 转换

**成功率公式（v1.32 参数 + v1.34 口径）**：

```
qi = 委托等级索引；B = [1, 0.6, 0.48, 0.40, 0.32][qi]
D = 难度修正（简单+0.10/普通0/困难−0.10/噩梦−0.20，Lv3+ 特殊覆盖）
Δ = min(0.36, max(0, 玩家lv−qi) × 0.12)         // v1.32 等级差修正
health = 昨日日结算分 × 0.002 × A               // v1.34：按 prev_health_score，新号第一天=0
E = min(eCap[qi], 装备+技能+分类率)              // eCap = [.10,.10,.08,.08,.06]
N = 昨日未早睡 −0.15 + 熬夜减免
最终 = min(hardCap, max(floor, B+D+Δ+health+E+N+餐+charm+rare+nm)) + 狼 + 宠物
hardCap = [1, 0.95, 0.90, 0.85, 0.80]｜接取时锁定（accept 存 rate，settle 用锁定值）
```
