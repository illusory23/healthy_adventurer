# v1.73 传奇事件酒馆传闻

> 更新日期：2026-10-19
> 触发：用户指定「传奇事件出现时酒馆内增加相关传闻，每个传奇事件的传闻文本 7-9 条，出现时随机刷新 2-3 条，营造出酒馆内非常热闹、几乎所有人都在讨论这个大事件；或者神情紧张、小声交谈，仿佛下一刻天要塌下来了」。
> 范围：前端酒馆页、传奇事件状态、服务端状态与迁移、静态数据导出、三方对拍、测试与文档。

---

## 1. 设计

| 项目 | 规则 |
|---|---|
| 触发条件 | 当前有传奇事件（含「预览」低语）且传闻属于该事件 |
| 传闻池 | **16 个传奇事件 × 8 条**（均在 7~9 条区间） |
| 每次展示 | 从对应事件池中随机抽 **2~3 条**，不重复 |
| 刷新时机 | 传奇事件出现 / 跨天重掷预览时生成；同一天内保持不变 |
| 清除时机 | 接取传奇事件、预览跨天消失、事件结束 |
| 氛围 | 两种基调混写：整间酒馆沸沸扬扬都在谈论；或压低声音、神情紧张，仿佛下一刻天要塌下来 |
| 位置 | 酒馆页「🍺 酒馆传闻」卡下方，金色描边高亮卡 |

标题：`🔥 今夜，酒馆里只有一个话题：<事件名>`。预览状态下底部提示「这些说法还没坐实——有人说看见了，有人说只是风。」；正式出现时提示「消息已经坐实……」。

## 2. 数据

- 前端 `LEGEND_RUMORS`：16 个键，与 `LEGEND` 事件名一一对应，每键 8 条文本。
- `newLegendRumor(name)`：抽 2~3 个不重复下标，返回 `{name, date, idxs}`；前端用 Fisher–Yates 洗牌，随机源退化（恒返回同一值）时也能终止且不重复。
- 服务端 `_new_legend_rumor(name)` 用 `random.sample`，同样保证不重复。
- 服务端 `LEGEND_RUMORS = DATA["LEGEND_RUMORS"]`，由 `tools_export_data.js` 导出。
- 状态字段：`legendRumor`（前端）/ `legend_rumor`（服务端），结构 `{name, date, idxs}`。

---

## 3. 逻辑

| 场景 | 前端 | 服务端 |
|---|---|---|
| 传奇预览出现 | `S.legendRumor = newLegendRumor(...)` | `s["legend_rumor"] = _new_legend_rumor(...)` |
| 正式传奇出现 | 同上 | 同上 |
| 预览跨天清除 | `legendRumor = null` | `legend_rumor = None` |
| 接取传奇 | `legendRumor = null` | `legend_rumor = None` |
| 旧档已有事件但无传闻 | 渲染时补生成一次 | `migrate_state` 补生成一次 |
| 事件已结束 | — | `migrate_state` 清理残留 |

旧档迁移不会丢失：完成「金龙宝藏的谈判」后同时解锁的四条金属龙委托、以及此前所有 v1.72 数据均不受影响。

## 4. 界面

酒馆页在普通传闻卡之后插入一张高亮卡：

- 标题带事件名；
- 逐条显示抽中的 2~3 条传闻，左侧金色竖线；
- 底部按「预览 / 正式」显示不同氛围提示；
- 未出现传奇事件时不渲染该卡；
- 文本为静态策划文案，直接插入 `innerHTML`（不含玩家输入）。

新增断言覆盖：

- 16 个传奇事件均有传闻池，每池 7~9 条；
