## 二、实施明细

### A. 改名与门槛

- 「医务室」→「疗养圣所」全站改名（卡片标题 / 按钮 alert 标题 / addLog / 提示语 / 注释 12+ 处）；emoji 🏥 → 🕊️。
- **门槛移除**：客户端两层 `takeSickLeave` 的 `guildIdx() < 3` 拦截删除、renderHealth 卡片的 `if(guildIdx() >= 3)` 包裹删除、服务端 `take_sick_leave` 的公会检查删除。初始（F 级 0 声望）即可见、可用。

### B. 每月 2 天 → 3 天

- `SICK_MONTHLY = 3`（客户端层 1 常量 + 服务端常量）；卡片 `${SICK_MONTHLY}` 自动跟随；上限用例改「第 4 次被拒」。

### C. 病假日 = 封存日（评分锁定 59 + 打卡封闭）

- **评分锁定**：`calcHealth()`（客户端）/ `calc_health(s)`（服务端，`sick_today(s)` 判定）双端覆盖为 **59**——显示 / 23:30 结算 / 归档 history / 次日 buff 全链路同口径（`SICK_LOCK_SCORE = 59`）。
- **打卡封闭**：客户端两层 + 服务端三入口（`toggle_task` / `toggle_meal` / `add_multi`）一律拒绝「今日病假已封存」；**打卡类道具**（安眠护符 / 清醒符咒 / 活力药水）同封存（`use_item` 双端）；renderHealth 中任务 / 三餐 / 多次任务按钮置灰 `disabled`，评分卡与圣所卡显示「病假封存 · 评分锁定 59 · 打卡关闭」。
- **补请昨日**：昨日记录 `score` 直接改写为 59（拉低周/月平均——保连击的代价闭环；已结算的声望不追回）。
- **日结算消息**追加「🕊️ 疗养圣所·病假：本日评分按 59 分锁定结算」。

### D. v1.61b 修复（用户实机反馈）

## 六、v1.61e · 两栏布局观感修正（用户三条反馈）

## 十五、v1.61n · HUD 底部空隙修正（用户反馈）

### 用户反馈

> 手机端顶部滑动栏和钱币等信息中间还有较大的空间。

### 根因

`#hud` 的底部内边距自早期版本起就**误用了 `env(safe-area-inset-top)`**：

```css
/* 旧（错）：bottom = 8px + inset-top；刘海机型把顶部安全区垫到了底部 */
padding:8px 12px calc(8px + env(safe-area-inset-top,0));
padding-top:calc(8px + env(safe-area-inset-top,0));
```

`viewport-fit=cover` 下刘海机型 `safe-area-inset-top` ≈ 47~59px——页签栏移至顶部后，这段 ≈55px 的空隙正好显现在 **HUD（钱币信息）与页签栏之间**（此前显现于 HUD 与内容之间，不易察觉）。

### 修复

```css
/* 新：上 8px + inset-top（状态栏避让）／下 8px */
padding:calc(8px + env(safe-area-inset-top,0)) 12px 8px;
```

- 普通机型 / 桌面端 inset-top = 0 → 与旧值等价（8/8），无影响；刘海机型底部回收 ≈47~59px。
- 双端手动镜像（game.html + 原型 <style>）。
