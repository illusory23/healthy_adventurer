## 一、会话摘要

### 1. 用户需求（按提出顺序）

1. 委托有效时间往前延长 1 小时。
2. 探索结算过简，结算弹窗疑似有延迟——排查并优化。
3. 探索进行时仍可查看可探索地点列表。
4. 稀有图纸公会 C 级开放太晚（玩家等级早已 Lv3+）→ 降到 D。
5. 材料价值再参差一些（同品阶价格太规整）。
6. 材料市场公会 C → D。
7. 澄清「往前延长 1 小时」= 窗口起点提前；最终确认**前三班提前、末班保持 21:00–23:30**。
8. 图纸价格也按装备效果拉开，同一品阶不再统一价。
9. 检查贡献 / 活力点是否重复奖励；确认后选择「日结算保留、区间奖励去掉贡献 / 活力」。
10. 删除游戏内「贡献 / 活力点只发一次」的解释文案。
11. 更新文档移入 `ai修改对话记录/`，与会话摘要整合为一个文件；以后相关文档都放这里。

### 2. 最终设计口径

- **刷新点**：07:00 / 11:00 / 17:00 / 21:00；窗口 07–09 / 11–13 / 17–19 / 21:00–23:30（末班 2.5 小时）。
- **精力恢复 / 首次刷新判定**：07:00（与首刷新同步）。
- **探索**：进行中仍显示地点列表；结算改为结构化详情弹窗；到点约 0.5 秒内弹出。
- **解锁**：稀有图纸 / 材料市场均为公会 D 级。
- **材料价格**：同品阶价差 5–12 倍，各品阶总价值基本持平。
- **图纸价格**：116 张按 `GEAR[6]` 逐张定价，同档价差约 1.5–4.4 倍。
- **奖励**：日结算发放声望 / 贡献 / 活力点一次；次日区间奖励只保留委托报酬 / 精力。

### 3. 实现与排错要点

- **探索结算延迟**根因：服务端完成判定在 `catch_up`，前端仅 20 秒轮询，且 `flushResults` 队列播放期间不再重试；用 `exploreActive.finishTs` 前台定时器（约 0.5 秒）+ 队列结束 300ms 续接修复。
- 服务端 `_payload` 为 `view = dict(s)` 整体下发，`explore_result` 新增的 `h / exp / loot / ts` 无需白名单。
- **图纸价格**写入 `GEAR` 第 7 字段；前端 `bpInfo()`、后端 `buy_blueprint()`、`图纸总表.csv` 同源；旧数据回退到档位价。
- **重复奖励**根因：`day_settle` 与 `buff_next` 各发一次贡献 / 活力点（v1.59b 为「与结算表同步」把同样的值写进区间奖励），两者无互斥；现 `buff_next` 只写 `pay/energy`，旧存档未领取的区间奖励补发保留。
- 测试曾因硬编码旧价格 / 旧窗口失败，已改为动态或新值；冒烟与桥接各修正一处良好档文案断言。
- **同步顺序**：Flask → 创造模式原型（`_sync_proto.py --apply`）→ 体验版；数据表 21 张重生成；三方对拍全过。

### 4. 验证与收尾

# v1.75 · 委托窗口 / 探索结算 / 解锁节奏 / 材料价格

> 本文记录 v1.75 的六项用户指定改动（2026-10-20）。三端同步（Flask 前端 / 创造模式原型 / 体验版），数据表 21 张重生成。

## 1. 委托接取窗口：1 小时 → 2 小时

| 项 | 改动前 | 改动后 |
|---|---|---|
| 常规刷新点窗口 | 1 小时 | **2 小时** |
| 对应时段 | 08–09 / 12–13 / 18–19 | **08–10 / 12–14 / 18–20** |
| 最后一次（21:00） | 至 23:30（2.5 小时） | 不变（已到停接时刻） |
| 节日窗口 | 常规 1→2 小时 | **常规 2→3 小时**；最后一次仍延至次日 00:30 |
| 时之怀表重置 | 1 小时 | **2 小时** |

实现：`game.py::POOL_WINDOW_MS` 与 `game.html::POOL_WINDOW_MS` 同步改为 120 分钟；窗口日志 / 过期提示 / 委托说明 / 节日欢迎窗 / 参数速查全部改为动态或 2 小时口径。

## 2. 探索进行中仍可查看地点列表

原实现中 `S.exploreActive` 为真时，探索卡只显示「探索中」进度条，整块地点列表被隐藏。现改为：

- 探索卡始终渲染**可探索地点列表**（按探索点消耗低→高）；
- 当前进行中的区域高亮并标注「探索中」，其余行半透明但**仍可点击查看详情 / 掉落 / 经验**，便于规划下一次出行；
- 详情弹窗中的「正在探索此区域」状态保持不变，可前往判定仍与 `doExplore` 一致。

## 3. 探索结算：结构化详情弹窗

原结算仅一行「获得：……」。现改为独立详情弹窗（`showExploreSettlement`，原型与 Flask 共用）：

- 头部：区域 / 耗时 / 经验 +N；
- 分组：📦 材料（品阶徽章 + 数量）、🎒 规则道具、🛡️ 装备、💰 铜币、🐾 宠物拾取、🗝️ 其它；
- 旧宝箱开出的物品标注「旧宝箱」来源；
- 底部：收获项数、材料总数、按交易所卖出价折算的**参考价值**；
- 空手时显示「空手而归……」与经验说明。

服务端 `explore_result` 新增 `h / exp / loot / ts` 字段；旧档仅有 `msg` 时前端自动回退为原单段文案。日志 `msg` 保持不变，兼容既有测试与存档。

## 4. 探索结算弹窗到点即时弹出

根因：探索完成判定依赖服务端 `catch_up`，而前端只在 20 秒轮询 / 手动请求时触发，故结算弹窗最多延迟约 20 秒；若恰好有结算队列在播放，还要再等下一轮。

修复：

- 客户端在 `render()` 中按 `exploreActive.finishTs` 设置**前台唤醒定时器**（约 0.5 秒后调用一次 `tick`），探索到点立即拉取 / 本地结算；
- `flushResults` 队列播完后 300ms 立即接续 `maybeShowExploreFlow()`，不再等下一轮轮询；
- 探索结果展示后本地先清空 `S.exploreResult` 再 ack，防止 ack 往返期间重复弹窗；
- 服务端 `explore_finish_check` 本身保持幂等，重复调用无副作用。

## 5. 解锁节奏：稀有图纸 / 材料市场 C → D

| 内容 | 改动前 | 改动后 |
|---|---|---|
| 图纸商店·稀有 | 公会 **C** 级（约第 67 天） | 公会 **D** 级（约第 39 天） |
| 材料市场 | Lv3 + 公会 **C** | Lv3 + 公会 **D** |

理由：Lv3 约第 33 天到达，D 级约第 39 天——玩家升到 Lv3 后不久即可购买稀有图纸 / 使用市场，不再出现「等级早已 Lv3+、装备 / 交易却还卡在 C 级」的断层。史诗 / 传说图纸仍为 A / S 级，市场史诗材料仍另需 Lv4。

实现：`BP_SHOP["稀有"].guild 3→2`、`CFG.market.unlockGuild 3→2`、`market.py` 默认值与文案、`game.py::buy_blueprint` 门槛表、前端提示、测试断言同步。

## 6. 材料价值参差化

同品阶内价格从「几乎一条直线」拉开为明显梯度，各品阶总价值基本持平（±10% 内）：

| 品阶 | 改动前区间（约） | 改动后区间 | 最高/最低 |
|---|---|---|---:|
| 普通 | 30–80 铜 | **10 铜 – 1.2 银** | 12 倍 |
| 精良 | 3.2–8 银 | **1.4–15 银** | 10.7 倍 |
| 稀有 | 27–50 银 | **10 银 – 1.2 金币** | 12 倍 |
| 史诗 | 4–9.5 金币 | **2–18 金币** | 9 倍 |
| 传说 | 30–60 金币 | **15–90 金币** | 6 倍 |

定价口径：常见易得材料（止血草 / 松脂 / 净化石 / 暗影草 / 时间沙）走低档；稀有部位与魔性结晶（石英 / 紫水晶 / 星辉石 / 魔鬼徽记 / 龙心）走高挡。交易所卖出/买入区间、市场参考价与价格上下限全部由基准价自动派生，无需另改。

# v1.76 · 刷新点整体提前 / 图纸逐张定价 / 奖励去重

> 本文记录 v1.76 的三项用户指定改动（2026-10-20）。同日 v1.75 的「接取窗口 1 → 2 小时」在本版按用户澄清修正为**前三班向前延长 1 小时**；末班保持 21:00–23:30 不变。

---

## 1. 前三班刷新点提前 1 小时（末班保持 21:00）

| 项 | v1.75（旧） | v1.76（新） |
|---|---|---|
| 刷新点 | 08:00 / 12:00 / 18:00 / 21:00 | **07:00 / 11:00 / 17:00 / 21:00** |
| 常规接取窗口 | 08–10 / 12–14 / 18–20 | **07–09 / 11–13 / 17–19** |
| 末班窗口 | 21:00–23:30（2.5 小时） | **21:00–23:30（2.5 小时，不变）** |
| 精力恢复 / 首次刷新判定 | 08:00 | **07:00**（与首刷新同步） |
| 23:30 停接 | 不变 | 不变 |
| 节日窗口 | 各 +1 小时（末班至次日 00:30） | 不变 |

实现：

- `game.html::CFG.refreshHours` 与 `static_data.json` / `game.py::CFG`：`[8,12,18,21]` → `[7,11,17,21]`。
- `LAST_POOL_WINDOW_MS` 保持 **150 分钟**（21:00 + 2.5h = 23:30）；`POOL_WINDOW_MS` 保持 120 分钟（07–09 等）。
- 精力恢复：前端 `now.getHours() >= CFG.refreshHours[0]`、后端 `now.hour >= CFG["refreshHours"][0]`——不再硬编码 8 点。
- 公会额外委托 / 特权委托 / 时间沙漏委托均挂在「每日首次刷新」上，随 `refreshHours[0]` 自动移到 07:00；相关文案同步。
- 节日欢迎弹窗末班文案：「21:00 班延至次日 00:30」。
- 刷新说明、教程、日志、过期提示、时之怀表（末班 2.5 小时）全部按班次动态显示。

> 为什么前三班要提前：接取窗口从批次生成时刻起算。若要 07:00 就能接 08:00 批次，批次必须在 07:00 生成——等价于刷新点提前 1 小时。因此 08/12/18 三班前移为 07/11/17，窗口关闭时刻仍为 09/13/19；末班 21:00 不动，窗口保持 21:00–23:30 与 23:30 停接自然衔接。

## 2. 图纸价格逐张差异化

v1.75 之前图纸按品阶统一价（普通 20 银 / 精良 1.5 金 / 稀有 9 金 / 史诗 42 金 / 传说 5 铂金）。不同装备效果差异很大，统一价不合理。

现改为**每张图纸单独定价**，价格写入 `GEAR` 第 7 字段（`GEAR[6]`，单位铜币），商店、后端扣款、数据表全部读取同一字段：

| 品阶 | 价格区间（铜币） | 展示区间 | 同档最高/最低 |
|---|---:|---|---:|
| 普通 | 1,625 – 2,425 | 16.3 – 24.3 银 | 1.49 倍 |
| 精良 | 10,250 – 23,500 | 1.03 – 2.35 金币 | 2.29 倍 |
| 稀有 | 72,500 – 142,500 | 7.25 – 14.25 金币 | 1.97 倍 |
| 史诗 | 260,000 – 705,000 | 26 – 70.5 金币 | 2.71 倍 |
| 传说 | 2,000,000 – 8,850,000 | 2 – 8.85 铂金币 | 4.43 倍 |

定价因子：

1. **效果强度**（主权重）：全委托成功率 / ★每日接取上限 / ★同时进行上限 / 材料获取 / 传奇事件成功率 / 稀有事件概率等权重最高；分类成功率、分类精力消耗、分类报酬、委托经验、公会贡献依次递减；多词条按段累加。
2. **主材料价值**：同档内材料越贵，图纸略贵（±15%）。
3. **稳定扰动**：按装备名做确定性哈希（±15%），同效果的不同装备也不会完全同价；不随刷新变化。
4. **同档归一**：每档价格均值保持原统一定价附近（普通 ≈2,000 / 精良 ≈15,000 / 稀有 ≈90,000 / 史诗 ≈420,000 / 传说 ≈5,000,000 铜），只拉开差距，不整体通胀。

实现细节：

- `GEAR` 增加第 7 字段：`["铜剑","普通","武器",0.01,"—","铜矿石×3",2300]`；不可购买的 19 件（成就 / 传奇事件 / 大师专属）保持 6 字段。
- 前端 `bpInfo()`：优先 `g[6]`，旧档 / 旧数据回退到 `BP_SHOP` 档位价；图纸商店逐张显示 `fmtMoney(g[6])`，下一档预告显示区间。
- 后端 `buy_blueprint()`：优先 `g[6]` 扣款，旧数据回退档位价；与前端同源，不再可能出现「显示一个价、扣另一个价」。
- 数据表 `图纸总表.csv` 价格列改为逐张价；`装备总表.csv` 不变。
- 新增测试：每个品阶内至少 1.4 倍价差、多种价位；后端按 `GEAR[6]` 扣款（草药袋 1,625 铜）。

## 3. 修复「贡献 / 活力点」重复发放

### 现象

健康页同时列出：

- **【当日 23:30 结算】** 声望 / 贡献 / 活力点（完美 +8 / +6 / +5）
- **【次日区间奖励】** 委托报酬 +15% / 精力 +10 / **贡献 +6 / 活力点 +5**

两项都在代码里真实发放，不是文案重复：完美日一天实际共得 **贡献 +12、活力 +10、声望 +8**。

### 根因

两套奖励系统各自实现了一遍贡献 / 活力点：

1. `day_settle` / `daySettle`（日结算）：按当日评分直接加 `rep/con/vit`，同时生成次日的 `buff_next`；
2. `buff_next`（次日区间奖励）：v1.59b 为「与结算表同步」又把同样的 `con/vit` 写进了次日 buff，次日 `apply_buff_claim` / `applyBuffClaim` 再发一次。

两处没有互斥标记，因此叠加。

### 修复（用户选择：日结算保留，区间奖励去掉贡献/活力）

- `day_settle` / `daySettle` 生成 `buff_next` 时只写 `pay` / `energy`（虚弱档仍写 `energyPct`），不再写 `con/vit`。
- `apply_buff_claim` / `applyBuffClaim` 保留：仅用于**旧存档**已存在 `con/vit` 的区间奖励补发（向后兼容），新存档的 buff 中 `con/vit` 为 0，不再产生「区间奖励到账」消息。
- 健康页说明、「昨日结算」弹窗、`gradeInfo` 区间效果文案全部去掉区间奖励中的贡献 / 活力点，并加注「贡献 / 活力点只在日结算发放一次」。
- 修复后完美日：**声望 +8 / 贡献 +6 / 活力 +5（仅一次）+ 次日委托报酬 +15% / 精力 +10**。
